Спостереження:

Питання та роздуми:

- У яких випадках краще використовувати CSS Modules, а коли Tailwind CSS?

- Мені здається корисним, що Next.js дозволяє обирати спосіб стилізації залежно від потреб проєкту.

## 03. Оптимізація шрифтів та зображень

Скріншоти:

- [04-fonts-code](./screenshots/04-fonts-code.png)
- [05-homepage-browser](./screenshots/05-homepage-browser.png)

Що було зроблено:

- Було пройдено третій розділ офіційного туторіалу Next.js — **Optimizing Fonts and Images**.
- Додано та використано шрифт `Lusitana` через вбудований механізм `next/font`.
- Підключено шрифт до тексту на головній сторінці.
- Ознайомилась з оптимізацією зображень у Next.js.
- Переглянула, як компонент `Image` допомагає автоматично оптимізувати зображення.

Спостереження:

- Next.js має вбудовану підтримку оптимізації шрифтів, тому не потрібно вручну підключати їх через зовнішні CSS-посилання.
- Використання `next/font` допомагає покращити продуктивність і уникнути зайвого завантаження шрифтів.
- Компонент `Image` є зручним, тому що дозволяє оптимізувати розмір, якість і завантаження зображень.
- Для коректного використання зображень потрібно вказувати `width`, `height` або інші параметри, щоб сторінка не “стрибала” під час завантаження.

Питання та роздуми:

- Цікаво, наскільки сильно `next/font` впливає на швидкість завантаження сторінки у великих проєктах.
- Варто краще розібратися, коли краще використовувати звичайний тег `<img>`, а коли компонент `Image`.
- Мені здається корисним, що Next.js одразу пропонує інструменти для оптимізації продуктивності.

## 04. Створення макетів і сторінок

Скріншоти:

- [06-dashboard-page](./screenshots/08-dashboard-page.png)
- [07-folder-structure](./screenshots/07-folder-structure.png)

Що було зроблено:

- Було пройдено четвертий розділ офіційного туторіалу Next.js — **Creating Layouts and Pages**.
- Ознайомилась зі структурою маршрутизації в папці `app`.
- Створено сторінки для dashboard-частини застосунку.
- Додано спільний layout для dashboard-сторінок.
- Перевірила роботу нових сторінок у браузері через локальний сервер.

Спостереження:

- У Next.js маршрути створюються на основі структури папок у директорії `app`.
- Файл `page.tsx` відповідає за окрему сторінку маршруту.
- Файл `layout.tsx` дозволяє створити спільну структуру для кількох сторінок.
- Це зручно, тому що повторювані елементи інтерфейсу можна винести в один layout, а не дублювати на кожній сторінці.
- App Router робить структуру проєкту більш зрозумілою, оскільки маршрути напряму пов’язані з папками.

Питання та роздуми:

- Потрібно краще розібратися, коли варто створювати окремий `layout.tsx`, а коли достатньо звичайного компонента.
- Цікаво, як Next.js обробляє вкладені layouts у великих застосунках.
- Мені здається зручним, що структура URL формується через папки, бо це робить навігацію в проєкті більш логічною.

## 05. Навігація між сторінками

Скріншоти:

- [08-navigation-browser](./screenshots/08-navigation-browser.png)

Що було зроблено:

- Було пройдено п’ятий розділ офіційного туторіалу Next.js — **Navigating Between Pages**.
- Ознайомилась з навігацією між сторінками у Next.js.
- Використано компонент `Link` з `next/link` для переходів між сторінками без повного перезавантаження сторінки.
- Додано або перевірено навігаційні посилання в dashboard-частині застосунку.
- Перевірила роботу переходів між сторінками у браузері.
- Ознайомилась із визначенням активного посилання за допомогою `usePathname`.

Спостереження:

- Компонент `Link` у Next.js зручніший за звичайний тег `<a>`, тому що дозволяє переходити між сторінками швидше.
- Навігація працює без повного перезавантаження сторінки, що робить застосунок більш схожим на SPA.
- `usePathname` дозволяє отримати поточний шлях і використовувати його для підсвічування активного пункту меню.
- Для використання hooks, таких як `usePathname`, компонент має бути client component, тому потрібно додавати `"use client"`.

Питання та роздуми:

- Потрібно краще розібратися, коли компонент має бути server component, а коли client component.
- Цікаво, як Next.js оптимізує переходи між сторінками.
- Мені здається корисним підсвічування активного пункту меню, бо це покращує зручність користування застосунком.

- Налаштовано підключення до PostgreSQL бази даних.
- Додано змінні середовища для підключення до бази даних.
- Запущено seed-скрипт через маршрут `/seed`.
- Перевірено, що початкові дані були додані до бази даних або що необхідні таблиці вже існують.

Спостереження:

- База даних використовується для збереження інформації про користувачів, клієнтів, рахунки та доходи.
- Seed-скрипт потрібен для початкового заповнення бази тестовими даними.
- Повідомлення типу `already exists, skipping` не є критичною помилкою. Воно означає, що таблиця або розширення вже були створені раніше.
- Змінні середовища потрібно зберігати у файлі `.env.local`, але не можна додавати цей файл у GitHub, тому що він може містити секретні дані.
- Під час роботи з PostgreSQL може виникати помилка, пов’язана з prepared statements, яку можна виправити через налаштування підключення.

Питання та роздуми:

- Потрібно краще розібратися, чим seed-скрипт відрізняється від міграцій бази даних.
- Цікаво, як Next.js безпечно працює з базою даних на серверній стороні.
- Також варто краще зрозуміти, як правильно організовувати `.env.local` та `.env.example` у реальних проєктах.
